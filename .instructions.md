# Instruction: Always Update README.md

## Rule
Whenever you make a change that affects the usage, features, or setup of the project, you **must** update the README.md file to reflect those changes. This includes, but is not limited to:
- Adding, removing, or modifying features
- Changing configuration, dependencies, or setup steps
- Updating APIs, endpoints, or usage examples
- Introducing new conventions or workflows

## Rationale
Keeping the README.md up to date ensures that all contributors and users have accurate, current information about the project. This reduces confusion and onboarding time, and improves project maintainability.

## Example Prompts
- "Add a new API endpoint and update the README.md."
- "Refactor the setup process and make sure the README.md reflects the new steps."
- "Document the new feature in the README.md."

## Related Customizations to Consider
- Enforce changelog updates for significant changes
- Require code comments for public APIs
- Standardize README.md sections (e.g., Features, Setup, Usage, Contributing)

---
This instruction applies to all files and technologies in this repository. It is a **hard rule** for all contributors.
